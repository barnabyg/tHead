# Domain docs

Use a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

Before exploring the codebase, read the glossary and ADRs
relevant to the work. Proceed silently when these do not exist.
Create them lazily through domain modeling as terms and decisions
are resolved.

Use the glossary's terms in issues, proposals, code, and tests.
Reconsider unfamiliar terms or note real gaps for domain modeling.

Surface conflicts with existing ADRs explicitly, identifying the
decision and explaining why it should be reconsidered.
